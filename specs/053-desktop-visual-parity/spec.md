## Problem

1. **Desktop icon: white tile.** Every Windows surface (installed EXE, NSIS
   installer, desktop/Start-Menu shortcuts, taskbar, window titlebar/Alt-Tab,
   `masarx://` DefaultIcon) resolves to a single file, `apps/desktop/build/icon.ico`,
   generated as a **white squircle tile + mark** (`scripts/generate-icon.mjs`
   default style). The PWA icon (web "any" ladder) is the bare mark on
   transparency, which the owner prefers. Owner decision 2026-11-19: swap the
   desktop icon to the transparent PWA look; **web icon assets stay untouched**
   (PWA-only).
2. **Home dashboard stretches in the desktop shell.** `Layout.tsx` desktop
   `<main>` (`relative flex min-h-0 w-full flex-1 flex-col overflow-hidden pe-4`)
   has no `max-w-*`/start padding — the web variant caps at
   `max-w-7xl mx-auto px-3 sm:px-6 lg:px-8`. The home quick-actions grid is
   full-width `lg:grid-cols-12` and the hero card is `lg:col-span-5` → ≈780px
   wide on a maximized 1920px window vs ≈490px in the browser; Featured
   Summaries / Top Lectures stretch edge-to-edge as well. The "Ask ZANE AI"
   card is the most visible symptom.

## Scope

**In:**

1. `apps/desktop/scripts/generate-icon.mjs` — default style flips `squircle` →
   `transparent` (deterministic regeneration; `--style=` overrides still work;
   the built-in verifier is style-agnostic and unchanged).
2. `apps/desktop/build/icon.ico` + `build/icon-master.png` — regenerated
   transparent (7 frames 16/24/32/48/64/128/256, mark at 92%, same locked
   master).
3. Stale docs that mandate the white tile: `apps/desktop/electron-builder.yml`
   `win.icon` comment; `docs/BRANDING.md` §7.2 desktop regen line.
4. `apps/web/src/components/HomeClient.tsx` — root div gains a `home-shell`

5. `apps/web/src/styles/desktop-shell.css` — `.home-shell` capped to the web

**Out (non-goals):**

- Any file under `apps/web/public/` (manifest icons, favicon,
  apple-touch-icon) — owner directive, PWA-only.
- mac/linux icons (unconfigured; builds are `--win` only).
- Width of other desktop pages (subjects, quizzes, chat keep their current
  geometry, including `main`'s `pe-4` from spec 046).
- Vertical rhythm / spacing of the home page.

## Follow-up (2026-11-19, evening) — "still white" on the desktop + ICO frame hardening

**Why the desktop still showed the white icon:** the new build had never been
installed — `Masar X.lnk` (Nov 18) still targeted the old exe at
`AppData\Local\Programs\Masar X\Masar X.exe`; the rebuilt
`Masar X-Setup-x64.exe` sat uninstalled in the worktree's `out/`. The two other
Masar icons on the desktop are unrelated: **"Masar X (1)"** is an **Edge PWA
shortcut** (`msedge_proxy.exe --app-url=https://masarx.vercel.app/`) whose
`.ico` Edge bakes itself — probed byte-level: fully transparent art, BMP/DIB
frames ≤64 + PNG 256, no dark tile baked (its dark desktop tile was a stale
icon-cache rendering, cleared by a cache refresh); **masarx_next**'s dark tile
is the owner's own `C:\ICONS\masarx-folder-dark-256.ico` via the repo-root
`desktop.ini`.

**Hardening (this follow-up):** the hand-rolled `buildIco()` wrote PNG frames
for every size; PNG-in-ICO frames below 256 are mishandled by some shell icon
consumers (alpha dropped → transparent art renders as a black tile — invisible
while the art was opaque white). The writer now emits the battle-tested layout
Chromium itself uses for PWA shortcut icons: **BMP/DIB (BITMAPINFOHEADER +
32bpp straight BGRA bottom-up + zeroed 1bpp AND mask) for 16–128, PNG only for
256**. The verifier is format-aware (frame format/bpp/dims) and gained a
**corner-alpha assertion per style** (≤8 for transparent/squircle, 255 for
square) read straight from the ICO bytes, so an alpha-dropping writer can never
pass again.

**Install + cache:** the rebuilt Setup was installed over the old per-user
install (assisted wizard driven via computer-use — note: `/S` is ignored by
this assisted installer, it opens the wizard and idles), icon cache refreshed
with `ie4uinit.exe -show`, and the installed exe's icon decodes transparent
through the GDI shell path (corner alpha 0). Desktop/taskbar visual
confirmation: owner eyeball.
