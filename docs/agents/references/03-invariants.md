# Project invariants (the rules you cannot break)

| # | Rule | Why |
|---|---|---|
| I1 | Service-role and AI provider keys stay **server-side only** | RLS depends on it; CI runs `ai-endpoint-grep` + gitleaks on built artifacts |
| I2 | TypeScript end-to-end: `Database` types + Zod schemas in `packages/shared` | One source of truth across web/desktop/mobile |
| I3 | i18n for **every** user-facing string. No hardcoded Arabic in components | 46 namespaces in `packages/shared/src/messages/{ar,en}/` |
| I4 | All OAuth callbacks live under `[locale]/auth/callback/` | See [01-gotchas.md](./01-gotchas.md) §3 |
| I5 | `pnpm.neverBuiltDependencies` lives in root `package.json` under `"pnpm"` | See [01-gotchas.md](./01-gotchas.md) §8 |
| I6 | Electron version pinned exact (no `^`/`~`) in `apps/desktop/package.json` | See [01-gotchas.md](./01-gotchas.md) §11 |
| I7 | `ThemeScript.tsx` uses native `<script>` + `suppressHydrationWarning` | See [01-gotchas.md](./01-gotchas.md) §19 |
| I8 | Never destructive git ops (`stash drop`, `reset --hard`, `checkout --`, `clean -fd`) on a dirty tree without explicit user consent | See [01-gotchas.md](./01-gotchas.md) §20 |
| I9 | **No direct file deletion.** Agents never run `rm`/`git rm`/`del` on project files. To retire a dead or obsolete file: ask the user explicitly first, and on approval **move it to `.trash/`** (mirroring its original path; `.trash/` is gitignored) instead of deleting | Deletion from the working tree is irreversible; the user audits every removal and keeps a local archive |
| I10 | **Pasted model output is welcome — Validate & Adapt.** Raw copy-pasted text from other AI models is accepted as normal input (this is the user's primary phone-first workflow), but the agent must run full engineering validation before executing: match every snippet and claim against the actual repo state and real installed library versions, fix errors and hallucinations, adapt paths/names/APIs to project conventions — never blind application, never absolute rejection | Pasted model answers routinely reference files/APIs/states that don't exist here; validating and adapting before executing is what prevents AI-spaghetti accumulation |
| I11 | **Spec-first workflow.** No writing or modifying code for any task beyond trivial, direct fixes without a technical spec prepared and **approved by the user** first | Prevents unplanned dives into large/complex files and unreviewed architectural drift; see [10-spec-first.md](./10-spec-first.md) |
| I12 | **MVP Lock RETIRED** — lifted permanently by owner decision 2026-11-02; `09-mvp-lock.md` deleted per its "delete on lift" note. Work sizing now flows through request classification (question / light / full) instead of a lock | Owner lift 2026-11-02 |
| I13 | **Brand identity is frozen in `docs/BRANDING.md`.** Never describe the platform as a summaries-only platform ("منصة ملخصات" / "Study Summaries Platform"). Use the unified definition verbatim: AR "مسار إكس — منصتك الجامعية المتكاملة: مواد، شروحات، ملخصات، بنوك أسئلة، ومساعد ذكي" / EN "Masar X — Integrated University Learning Platform: study materials, lectures, summaries, quizzes & AI tutor". Feature order is always: materials → lectures → quizzes → courses → summaries (one part) → AI | Prevents identity drift back to "summaries platform" in metadata, footers, FAQ, llms.txt and AI answers |
| I14 | **Agent isolation (revised 2026-11-04, owner decision).** One agent session = one branch = one worktree — git itself forbids checking the same branch out twice, so the `.agents/<task>.md` claim-file ceremony stays RETIRED. The primary checkout belongs to the owner; agents never write in it. Worktrees live **outside the repo** at the tool-neutral path `../masarx-wt/<branch-slug>` — never inside the repo, never in tool-specific folders (`.kilo/`, `.cline/`, `.cursor/`, `.zcode/`, …). Pin the path on every interaction — shell via `git -C <path>`/`cd <path> && …`; file tools via absolute worktree paths, never repo-relative — the shell CWD may reset to the primary between commands (hit 2026-11-04). After merge: `git worktree remove <path> && git worktree prune`. Owner-directed maintenance/docs go through the normal PR flow (`main` is protected — direct pushes are rejected); never force-push or rewrite history (I16) (see [11-git-standards.md](./11-git-standards.md) §Agent Isolation) | The 2026-11-02 abolition of worktrees removed the only real cross-session lock; and nested tool-named worktrees inside the repo (`.kilo/worktrees/`) made agent edit tools hit the primary tree (2026-11-04 CWD/workspace-root incident). Correction: keep the lock, relocate it outside the repo, make it tool-neutral |
| I15 | **Git identity lock.** Never set or override the commit identity at command time: no `git -c user.name/user.email=…`, no `--author`, no `GIT_AUTHOR_*`/`GIT_COMMITTER_*` env vars — identity must come from the machine's git config only. If `git var GIT_AUTHOR_IDENT` does not resolve to the owner's email (`ahmedaboalayoun0016k@gmail.com` or `fotedev@users.noreply.github.com`), stop and ask. Never `--no-verify` and never `-c core.hooksPath=`. Enforced locally by `C:/Users/FOTE/.githooks/pre-commit` + `commit-msg` (repo-local `core.hooksPath` → absolute path outside the repo, so worktrees inherit it and `git clean` cannot remove it); on GitHub by the signed-commits ruleset | 2026-09-28/29: 7 commits landed on `main` as `Hermes Agent <hermes@nousresearch.com>` via a per-command `-c` identity override (Hermes session `20260928_130552_98eb20`, verified in its `state.db` tool calls). AGENTS.md was not read before the first commit, so this rule is also mirrored into agent memory |
| I16 | **Escalation lock.** Never modify repository rulesets, never force-push to any protected branch, and never rewrite pushed history (rebase/filter/amend of commits already on a remote) — unless the owner's explicit written confirmation appears in the same conversation message requesting that exact action. A plan alone, silence in reply to a question, or an agent-chosen default does **not** count as confirmation; if the action requires the owner to open a bypass window, ask who opens it and wait for the answer | 2026-10-03: `main` history rewrite (7 Hermes-identity commits → owner) required a force push that was only possible through a temporary ruleset bypass window on `Main Branch Protection` (ruleset 20299668). The rewrite itself was owner-requested and the plan was approved, but the sub-decision of who opens the bypass window was defaulted instead of waited on — the window was opened by the agent and closed ~30s later (ruleset History: 22:02:04 and 22:02:33 +02:00). Escalating irreversible/protected-state changes needs a written yes, not a default |
